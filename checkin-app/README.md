# 온라인선교 챌린지 체크 — 실 운영 웹앱

로그인 없이 학생 9명이 각자 기기에서 매일 체크할 수 있고, 관리자(단장님)는 PIN으로 들어가
실시간으로 전체 현황·랭킹을 보고 어떤 날짜든 직접 수정할 수 있는 앱입니다.
빌드 도구 없이 순수 HTML/CSS/JS + Firebase Firestore로만 만들어져 있습니다.

## 배포 전 꼭 알아야 할 것

- **로그인이 없다는 것 = 링크를 아는 사람은 누구나 쓸 수 있다는 뜻**입니다. 학생 그룹 안에서만
  링크를 공유하세요.
- 이름 선택은 학생 각자의 **기기에 저장**됩니다(로그인이 아님). 기기를 바꾸면 다시 선택해야 하고,
  같은 기기를 여러 학생이 같이 쓰면 "다른 학생으로 전환"으로 바꿔가며 써야 합니다.
- 오늘의 체크 순서는 정확한 "도착 시각"이 아니라 **체크 버튼을 누른 시각**입니다(학생이 직접
  누르므로 사실상 같은 의미입니다).
- Firestore 무료 요금제(Spark) 한도 안에서는 비용이 들지 않습니다. 이 앱 규모(9명, 33일)로는
  한도에 전혀 걸리지 않습니다.

## 1. Firebase 프로젝트 만들기 (5분)

1. [console.firebase.google.com](https://console.firebase.google.com) 접속 → 구글 계정으로 로그인
2. "프로젝트 추가" → 이름 입력(예: `songha-checkin`) → 애널리틱스는 꺼도 됩니다
3. 왼쪽 메뉴 **빌드 → Firestore Database** → "데이터베이스 만들기" → 위치는 `asia-northeast3(서울)` 추천
   → 처음엔 "테스트 모드"로 시작해도 되지만, 아래 3단계에서 규칙을 꼭 교체하세요
4. 왼쪽 메뉴 **⚙ 프로젝트 설정 → 일반** 탭 맨 아래 "내 앱" → `</>` (웹) 아이콘 클릭 → 앱 닉네임
   아무거나 입력 → "앱 등록"
5. 화면에 나오는 `firebaseConfig` 객체의 값들을 복사

## 2. 이 프로젝트에 설정 붙여넣기

`firebase-config.js` 파일을 열어 `firebaseConfig`의 6개 값을 방금 복사한 값으로 바꿔주세요.
`ADMIN_PIN`도 원하는 4자리 숫자로 바꾸세요(기본값 `2026`).

## 3. Firestore 보안 규칙 적용

Firebase 콘솔 → Firestore Database → **규칙** 탭 → `firestore.rules` 파일의 내용을 그대로
붙여넣고 "게시" 클릭. (이 규칙은 `checkins` 문서만 열어두고 나머지는 전부 막습니다.)

## 4. 배포 (Vercel 기준, 3분)

1. 이 저장소를 GitHub에 푸시되어 있는 상태 그대로 [vercel.com](https://vercel.com)에서
   깃허브 계정으로 로그인
2. "Add New → Project" → 이 저장소(`songha`) 선택
3. **Root Directory를 `checkin-app`으로 지정** (중요) → Framework Preset은 "Other" 선택
   → Build Command·Output Directory는 비워둔 채 그대로 "Deploy"
4. 배포가 끝나면 `https://프로젝트이름.vercel.app` 링크가 생깁니다. 이 링크를 학생들에게 공유하세요.
   `https://프로젝트이름.vercel.app/#admin` 이 관리자 화면입니다.

`firebase-config.js`를 나중에 다시 바꾸고 싶으면 파일을 고치고 다시 GitHub에 푸시하면
Vercel이 자동으로 재배포합니다.

## 데이터 구조

Firestore에 `checkins` 컬렉션이 생기고, 학생 한 명당 문서 하나(`s1` ~ `s9`)가 만들어집니다.

```
checkins/s1
  name: "장윤지"
  days: [true, false, true, ...]   // 33일치, index 0 = 9월 1일
  times: { "17": 1735689600000 }    // 체크한 날의 체크 시각(ms), 랭킹 계산용
```

## 알려진 한계

- 문서 하나를 두 사람이 정확히 같은 순간에 고치면 나중 저장이 이깁니다(트랜잭션 없음).
  학생 9명이 각자 자기 문서만 건드리는 구조라 실제로 부딪힐 일은 거의 없습니다.
- PIN은 코드에 평문으로 들어있는 가벼운 접근 차단이지 진짜 보안이 아닙니다.
